# ISS-20260512T151045280Z-TRAITBOUNDREF-STORES-RENDERED-DISPLA-644F8E6A: TraitBoundRef stores rendered display names

## 概要

TraitBoundRef still stores a name String generated by format_trait_ref_name. Even after parse_trait_ref_name was removed, the bound model keeps diagnostic/display text inside the static-check data structure.

## 対象

- `nepl-core/src/typecheck/traits.rs; nepl-core/src/typecheck/function_check.rs; nepl-core/src/typecheck/trait_check.rs; nepl-core/src/typecheck/trait_bound_apply.rs; nepl-core/src/typecheck/block_check.rs; nepl-core/src/typecheck/driver.rs; nodesrc/test_abstraction_static_verification_policy.js`

## 根拠

- `TraitBoundRef` は `name: String` を持ち、`format_trait_ref_name` で作った表示名を静的検査データ構造の中に保持していた。
- `trait_bound_apply.rs`、`function_check.rs`、`trait_check.rs` は診断や verbose log のために `bound.name` / `substituted_bound.name` / `bb.name` を参照していた。
- これにより、表示名を比較や再解析へ戻す退行を構造上防ぎきれていなかった。

## 問題

TraitBoundRef still stores a name String generated by format_trait_ref_name. Even after parse_trait_ref_name was removed, the bound model keeps diagnostic/display text inside the static-check data structure.

## 影響

The model does not fully separate compiler identity from diagnostic text, and future checks can accidentally start using rendered names again.

## 修正方針

Remove TraitBoundRef.name, generate display names only through a helper at diagnostic/logging boundaries, and add source policy checks that prevent reintroducing rendered bound fields or bound.name usages.

## 対応記録

- `TraitBoundRef` を `TraitBound` に改名し、旧 model 名を Rust 実装から削除した。
- `TraitBound` から `name: String` field を削除し、`trait_base_name` / `trait_args` / `trait_self_ty` だけを保持する形にした。
- 診断と verbose log は `TraitBound::display_name(ctx)` で表示名を境界生成するようにした。
- `nodesrc/test_abstraction_static_verification_policy.js` の `TraitBoundRef` baseline を 0 にし、`TraitBound` に rendered diagnostic name field が戻らないことを固定した。
