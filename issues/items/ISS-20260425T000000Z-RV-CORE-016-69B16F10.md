# RV-CORE-016: 深い HIR を artifact codegen pipeline が再帰処理して stack overflow する

旧 `doc/review20260425` から移行した Issue。新しい正の ID は `ISS-20260425T000000Z-RV-CORE-016-69B16F10`。

## 要約

artifact 生成に必要な HIR pass / codegen backend は、深い `HirExpr` を再帰的に走査します。`--check` は分離済みですが、実際の wasm 出力では drop insertion、monomorphize、move check、codegen precheck、wasm codegen のいずれかで native stack を消費し、診断ではなくプロセス異常終了になります。

## 影響

型検査上は正当な深い式でも、wasm artifact を生成できません。CI や配布ビルドで入力サイズ依存の compiler crash が残ります。

## 修正方針

artifact 生成側の HIR traversal を段階別に切り分け、深い call chain で再帰しない iterative visitor へ置き換えます。最低限、1105-call chain の wasm 出力が stack overflow せず成功する regression を追加します。

## 2026-04-28 追跡

### 再発状況

GH Actions の `rust-test` で `compile_wasm_accepts_deep_prefix_chain_without_codegen_stack_overflow` が再び native stack overflow していた。ローカルでも同じ 1105 prefix call chain の `compile_wasm` が再現した。

段階別に切り分けた結果、`drop_insertion` と `monomorphize` は単体で通るようにできたが、`prepare_module_for_codegen` は `move_check` で落ちていた。特に function body の最後の式は戻り値 escape 検査用に `escape_depth` が渡されるため、戻り値が参照を含まない i32 call chain でも iterative visitor を使えず、再帰 visitor に戻っていた。

### 追加対応

- `drop_insertion` に、Copy 値だけで構成された単純 call / construct tree を explicit stack で確認し、drop state 更新が不要な式では再帰 descent を避ける fast path を追加した。
- `move_check` は戻り値型が参照を含まない式では `escape_depth` の有無に関係なく iterative visitor を使うようにした。参照を含む式、参照 parameter、control-flow、raw memory など ownership / borrow semantics が必要な式は従来通り詳細経路へ残す。
- `check_pipeline` に drop insertion / monomorphize / move check / prepare / compile_wasm の段階別 regression を追加し、どの段階で再帰が戻っても検出できるようにした。

## 2026-04-28 raw effect summary 追加後の再発対応

GH Actions run `25022369695` の `rust-test` で、`compile_wasm_accepts_deep_prefix_chain_without_codegen_stack_overflow` が native stack overflow していた。手元でも次の 3 段階で再現し、起点は wasm codegen ではなく `move_check` の function raw alias summary 構築であることを確認した。

- `cargo test -p nepl-core --test check_pipeline compile_wasm_accepts_deep_prefix_chain_without_codegen_stack_overflow -- --nocapture`: stack overflow
- `cargo test -p nepl-core --test check_pipeline prepare_codegen_accepts_deep_prefix_chain_without_stack_overflow -- --nocapture`: stack overflow
- `cargo test -p nepl-core --test check_pipeline move_check_accepts_deep_prefix_chain_without_stack_overflow -- --nocapture`: stack overflow

原因は、通常の `visit_expr_with_escape` には simple expression 用の iterative fast path がある一方、raw memory effect summary 追加後の `build_function_raw_alias_summaries` は `block_raw_alias_summary` / `expression_raw_alias_summary` で深い direct call chain を再帰的に辿っていたことだった。さらに call summary の `$param:N` alias instantiation も nested call argument に対して `raw_addr_alias_from_value` を再帰していた。

今回の対応では、`expression_raw_alias_summary` に simple direct user call tree 専用の bottom-up fast path を追加した。leaf summary を explicit stack で集め、user function call の return alias / raw effect は `instantiate_function_raw_alias_summary_from_value_summaries` で child `ValueAliasSummary` から展開する。raw memory call、`get` / `mem_ptr_*` / `region_*` などの特別な raw alias 規則を持つ call、indirect call、control-flow、borrow/lifetime が絡む式は従来の詳細経路に残している。

## 2026-04-30 Resource IR lowering 追加後の再発対応

`run_move_check` が Resource IR gate も実行するようになった後、`prepare_codegen_accepts_deep_prefix_chain_without_stack_overflow` と `compile_wasm_accepts_deep_prefix_chain_without_codegen_stack_overflow` の deep prefix call chain が再び native stack overflow した。

今回の起点は旧 HIR move checker ではなく、`lower_hir_module_skeleton` から呼ばれる `resource/lower.rs` の `lower_expr_skeleton` だった。`Call` の各 argument を `lower_args_skeleton` で再帰的に下ろすため、1105 段の direct prefix call chain が Resource IR skeleton 生成時点で host stack を消費していた。

対応として、literal / unit / local read / function value / direct call だけで構成される単純 direct call tree を explicit stack による post-order lowering へ切り替えた。`get` / `get_field` は field projection 専用 lowering が必要なため fast path から除外し、control-flow、match、borrow など direct call 以外の構造は従来の詳細経路へ残した。direct call の ResourceOp 生成は `push_direct_call_skeleton` にまとめ、通常経路と iterative 経路で effect、call op、core mem wrapper semantics、raw address return semantics、raw memory operation の出力を共有する。

### 根拠

`RV-CORE-015` の check-only path 分離後、同じ 1105 identity prefix call chain を実際に artifact 生成すると、`compile_module` 後段で native stack overflow します。

再現:

- `cargo run -p nepl-cli -- -i tmp/rv-core-003-large.nepl --target core -o tmp/rv-core-003-large-rv-core-015.wasm`

### 問題

artifact 生成に必要な HIR pass / codegen backend は、深い `HirExpr` を再帰的に走査します。`--check` は分離済みですが、実際の wasm 出力では drop insertion、monomorphize、move check、codegen precheck、wasm codegen のいずれかで native stack を消費し、診断ではなくプロセス異常終了になります。

### 影響

型検査上は正当な深い式でも、wasm artifact を生成できません。CI や配布ビルドで入力サイズ依存の compiler crash が残ります。

### 修正方針

### 対応

monomorphize では非 generic 関数の元 HIR を clone せず移動し、type parameter mapping が空の具象関数では body 全体の再帰 substitute を避け、callee queue のみを iterative traversal で処理するようにしました。move check は borrow / control-flow に関わらない単純な値式を explicit stack で走査する fast path を追加し、既存の ownership semantics が必要な式は従来の分岐へ残しています。

wasm codegen precheck と signature / reachable collection は shared helper 側で recursive walk をやめ、explicit stack で `HirExpr` を辿るようにしました。さらに wasm lowering では単純な literal / variable / direct call tree を iterative post-order lowering できる path を追加し、1105 個の prefix call chain を native stack に積まずに wasm instruction へ落とせるようにしました。
