# RV-STDLIB-010: Result/Option の unsafe helper が通常コードに広く残っている

旧 `doc/review20260425` から移行した Issue。新しい正の ID は `ISS-20260425T000000Z-RV-STDLIB-010-BF35FCBB`。

## 要約

unsafe helper と明記されている `unwrap` 系が stdlib 内部の通常処理に残っています。境界チェック済みの箇所もありますが、前提が崩れると `unreachable` に落ち、Result として呼び出し側へ返せません。

## 影響

I/O、文字列、parser 系で入力依存の trap が起きやすくなります。エラーを値として扱う stdlib 方針と矛盾します。

## 修正方針

public API と input-dependent code では `unwrap` 系を禁止し、`match` で `Result` / `Option` を返します。内部不変条件だけに `unwrap_unchecked` 的な名前を付けて限定します。

## 検証

`rg "unwrap"` の許可リストを作り、stdlib test で unsafe helper の新規使用を検出します。

## 対応結果

stdlib の通常実装に広く残っていた `unwrap` / `unwrap_ok` / `unwrap_err` / `uwok` / `uwerr` と `#intrinsic "unreachable"` は、個別 issue へ分離して順に修正した。
2026-04-27 時点の全体再スキャンでは、許可する残存箇所は次に限定される。

- `stdlib/core/option.nepl`: unsafe helper `unwrap` の定義本体。
- `stdlib/core/result.nepl`: unsafe helper `unwrap_ok` / `unwrap_err` と短縮 alias の定義本体。
- `stdlib/core/test.nepl`: test helper の意図的な異常終了。
- `stdlib/std/streamio.nepl`: `ScannerReadable::scan` の default stub。これは `ISS-20260427T062158099Z-SCANNERREADABLE-DEFAULT-SCAN-TRAPS-W-FCBF9EF6` として独立 issue に分離した。

全 stdlib を対象にした `nodesrc/test_stdlib_no_unsafe_helpers.js` を追加し、上記 allowlist 以外の unsafe helper / unreachable が通常実装へ戻った場合に CI で失敗するようにした。
