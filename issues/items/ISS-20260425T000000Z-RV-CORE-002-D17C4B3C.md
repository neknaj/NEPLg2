# RV-CORE-002: typecheck.rs が巨大化しすぎて責務が分離できていない

旧 `doc/review20260425` から移行した Issue。新しい正の ID は `ISS-20260425T000000Z-RV-CORE-002-D17C4B3C`。

## 要約

型推論、trait capability、overload、名前探索、HIR lowering、effect 判定、import alias 補助、diagnostic recovery が 1 ファイルに集中しています。局所修正が別機能へ波及しやすく、性能改善も profiling point を切りにくい状態です。

## 影響

既知バグの根本原因を追いにくく、修正のたびに回帰範囲が広がります。`doc/neplg3/impl/compiler_structure.md` で示されている `check/`, `ty/`, `resolve/`, `hir/` 分割方針との乖離も大きいです。

## 修正方針

短期的には `Env`、overload 解決、prefix reduction、trait impl 検査を別 module へ切り出します。中期的には AST flat list から HIR への lowering を型検査結果と分離し、`resolve` / `ty` / `check` の依存方向を固定します。

## 検証

分割ごとに既存 `tests/compiler/**` と stdlib doctest を走らせ、ファイル移動だけの段階では出力 JSON の差分がないことを確認します。

## 2026-04-28 issue 整理

この issue は静的検査大規模修正の Stage 1、つまり module 境界の切り出しと責務分離を追跡する親 issue とする。`typecheck.rs` と `move_check.rs` の巨大化そのものを扱い、Resource IR の意味論は `ISS-20260425T000000Z-RV-CORE-009-58589A3F`、raw memory API / effect 境界は `ISS-20260427T132406497Z-CORE-MEM-RAW-MEMORY-OPERATIONS-BYPAS-DC67DF04` へ分ける。

完了条件は、behavior を変えない module 分割を先に行い、その後の Resource IR 移行で focused regression の範囲を狭められる状態にすることである。局所的な helper 追加だけで `typecheck.rs` / `move_check.rs` の責務集中を温存する修正は、この issue の解決とはみなさない。

## 2026-04-28 Stage 1 実装開始

`doc/neplg2/static_check_complexity_reduction_plan.md` の Stage 1「module 境界の切り出し」として、`move_check.rs` の raw memory helper 分類を `nepl-core/src/passes/move_check/raw_memory.rs` へ分離した。今回は behavior を変えず、`RawMemoryCallKind`、raw memory helper 名の分類、raw memory call kind 判定を子 module に移し、親 `move_check.rs` は raw memory 分類 API を呼び出すだけにした。

これは Resource IR 導入前に `move_check.rs` の責務境界を作る最初の実装であり、raw memory provenance そのものの意味論変更は行っていない。この issue は引き続き open とし、次は function summary / branch merge / place-provenance 型の module 化を進める。

## 2026-04-28 Stage 1 function summary 境界

Stage 1 の続きとして、`move_check.rs` から function raw alias summary の型と merge/dedupe 処理を `nepl-core/src/passes/move_check/summary.rs` へ分離した。対象は `ValueAliasSummary`、`RawMemoryEffectSummary`、`FunctionRawAliasSummary`、raw memory effect dedupe、branch/match 合流時の alias merge、child summary の effect 集約である。

HIR / context に依存する実際の summary 生成はまだ `move_check.rs` 側に残している。今回の目的は behavior を変えずに、現行の HIR summary を Resource IR summary へ置き換えるための型境界を先に作ることである。この issue は引き続き open とし、次は place/provenance state と branch snapshot/merge の分離を進める。

## 2026-04-28 Stage 1 raw place 境界

Stage 1 の続きとして、raw memory place の状態型と key/range helper を `nepl-core/src/passes/move_check/raw_place.rs` へ分離した。対象は `RawPlaceState`、`RawPlaceInfo`、raw place key の format/parse、offset 合成、unknown offset 判定、byte range overlap 判定である。

HIR / context を見る `raw_memory_place_key` や branch merge 本体はまだ `move_check.rs` 側に残している。今回の目的は、Resource IR の `StorageId` / `PointerProvenance` / `CellState` へ置き換わる純粋な raw place 表現を先に module 境界へ出すことである。この issue は引き続き open とし、次は branch snapshot/merge と context state の分離を進める。

## 2026-04-28 Stage 1 state 型境界

Stage 1 の続きとして、`move_check.rs` から state 型を `nepl-core/src/passes/move_check/state.rs` へ分離した。対象は `VarState`、`BorrowKind`、`BorrowBinding`、`ExprBorrow`、`FieldMove`、`FieldMovePath`、`BorrowCount`、`ResourceStateSnapshot` である。

branch/loop/match merge の処理本体はまだ `move_check.rs` 側に残している。今回の目的は、Resource IR の `ResourceState` / `BorrowState` / `CellState` に置き換える前に、現行 checker の状態表現を HIR 走査本体から独立させることである。この issue は引き続き open とし、次は branch snapshot/merge helper の module 化を進める。

## 2026-04-28 再レビューでの再オープン

remote main の borrow/raw memory 修正取り込み後、責務集中は解消していない。現時点の line count は `nepl-core/src/typecheck.rs` が 9582 lines、`nepl-core/src/passes/move_check.rs` が 5486 lines で、旧レビュー時の `typecheck.rs` 8759 lines より悪化している。

`typecheck.rs` には overload、trait lookup、match exhaustiveness、literal match、HIR lowering、module/import 補助、diagnostic recovery が同居し続けている。`move_check.rs` も borrow state、field move、raw memory provenance、function/enum/aggregate alias summary を 1 file で持つ状態になっており、S3/S4 self-host 移植時に `resolve/ty/check/hir/resource` へ分ける基準を Rust 側から読み取りにくい。

この issue は再度 open とし、self-host 移植前に少なくとも仕様境界を module 単位で切り出す。Resource IR そのものの設計は `ISS-20260425T000000Z-RV-CORE-009-58589A3F` で追跡し、この issue では typecheck/move_check の責務分離と regression scope 縮小を扱う。
