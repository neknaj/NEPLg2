# ISS-20260426T023624387Z-PIPE-004372E8: pipe 右辺の明示型引数付きネスト呼び出しが過剰に分断される

## 概要

通常呼び出しの writeln w <i64> cast 2 は compile できるが、pipe 右辺の |> writeln <i64> cast 2 では D3006 / D3013 / D3016 が連鎖する。

## 対象

- `nepl-core/src/typecheck.rs, nepl-core/tests/pipe_operator.rs, tests/compiler/pipe_operator.n.md`

## 根拠

- `RV-STDLIB-018` の調査で、`tests/stdlib/streamio.n.md::doctest#5` の `unwrap_ok open WriteStream::Stdio |> writeln <i64> cast 2` が `D3006 no matching overload found`、`D3013 pipe left-hand side did not reduce to a single value`、`D3016 expression left extra values on the stack` で失敗した。
- 同じ値を通常呼び出しの引数として `writeln w <i64> cast 2` と書いた場合は compile できることを最小再現で確認した。
- `tests/stdlib/streamio.n.md` は `let two <i64> cast 2; |> writeln two` へ分けると green になるため、streamio の overload 定義ではなく pipe 右辺の nested argument boundary が原因候補である。

## 問題

通常呼び出しの writeln w <i64> cast 2 は compile できるが、pipe 右辺の |> writeln <i64> cast 2 では D3006 / D3013 / D3016 が連鎖する。

## 影響

型変換や generic helper を inline で pipe 右辺へ渡す自然な書き方が使えない。stdlib 側では一時変数で回避できるが、compiler の call boundary 問題は残る。

## 修正方針

pipe 右辺の call reduction で、明示型引数付き prefix call が後続関数の引数式として閉じる範囲を通常呼び出しと同じ規則で保持する。
