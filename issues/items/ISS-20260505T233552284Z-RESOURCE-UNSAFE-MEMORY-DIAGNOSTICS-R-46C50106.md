# ISS-20260505T233552284Z-RESOURCE-UNSAFE-MEMORY-DIAGNOSTICS-R-46C50106: Resource unsafe memory diagnostics remain shadow-only

## 概要

ResourceEffectBoundaryDiagnostic::UnsafeMemoryInPureFunction is generated by Resource IR but resource_effect_boundary_diagnostic_to_error returns None. Pure raw memory outside a raw-memory-boundary still depends on older typecheck gates, so Resource IR is not authoritative for unsafe memory effect safety.

## 対象

- `nepl-core/src/compiler.rs, nepl-core/src/resource/effect.rs, nepl-core/tests/effects.rs`

## 根拠

- `ResourceEffectBoundaryEngine` は `EffectOp::UnsafeMemory` を pure function 内で見つけると `UnsafeMemoryInPureFunction` を生成する。
- しかし `resource_effect_boundary_diagnostic_to_error` はこの diagnostic に対して `None` を返していた。
- `resource_effect_boundary_diagnostic_is_raw_boundary_allowed` には raw-memory-boundary source を許可する分岐が既にあるため、error mapping 側を shadow-only にする必要はない。

## 問題

ResourceEffectBoundaryDiagnostic::UnsafeMemoryInPureFunction is generated by Resource IR but resource_effect_boundary_diagnostic_to_error returns None. Pure raw memory outside a raw-memory-boundary still depends on older typecheck gates, so Resource IR is not authoritative for unsafe memory effect safety.

## 影響

Stage 5 cannot rely on Resource IR as the effect boundary source of truth. Future lowering changes or migration paths could introduce unsafe memory operations that produce Resource IR diagnostics but are ignored by the compiler gate.

## 修正方針

Map UnsafeMemoryInPureFunction to an Effect::PureCallsImpure diagnostic when the source is not raw-memory-boundary-capable, keep the existing capability allowance, and update regression tests.

## 対応

- `UnsafeMemoryInPureFunction` を `effect.pure.calls_impure` の compiler diagnostic へ変換するようにした。
- raw-memory-boundary source capability による許可は既存の `resource_effect_boundary_diagnostic_is_raw_boundary_allowed` 側に残した。
- compiler unit test を shadow-only 期待から error mapping 期待へ更新した。
