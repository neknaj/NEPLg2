# RV-CORE-009: move/borrow/drop が Resource IR なしで後付け実装されている

旧 `doc/review20260425` から移行した Issue。新しい正の ID は `ISS-20260425T000000Z-RV-CORE-009-58589A3F`。

## 要約

Resource IR がなく、HIR 木を直接走査して所有権状態を推測しています。borrow の lifetime release、field move、auto drop と user drop の整合、branch merge が局所状態で処理されており、仕様化しづらいです。

## 影響

false positive / false negative の両方が起きやすく、stdlib の owning collection と組み合わせたときに double free や use-after-move を防ぎきれません。

## 修正方針

`doc/neplg3/impl/compiler_structure.md` の方針どおり HIR 後に Resource IR を導入し、move、borrow、region、drop elaboration を別 pass に分けます。drop 挿入前に ownership を確定し、auto drop は Resource IR 上で挿入します。

## 検証

branch/loop/borrow/field move/drop trait の compile_fail と should_panic を整理し、Resource IR dump の snapshot test を追加します。

## 関連ドキュメント

- [NEPLg2 静的検査の複雑化解消計画](../../doc/neplg2/static_check_complexity_reduction_plan.md)

## 2026-04-28 issue 整理

この issue は静的検査大規模修正の Stage 2-4、つまり Resource IR 型定義、HIR lowering、Resource IR 上の move/borrow/lifetime/drop obligation 検査を追跡する親 issue とする。

現行の raw alias summary、enum payload alias、aggregate field alias、function value raw effect summary は、Resource IR 導入までの暫定防壁として扱う。今後は同種の補助 summary を増やし続けるのではなく、`ResourceId`、`Place`、`StorageId`、`CellState`、`BorrowState`、`PointerProvenance` へ統合する。compiler 側の module 分割は `ISS-20260425T000000Z-RV-CORE-002-D17C4B3C`、stdlib raw API 移行は `ISS-20260427T204839136Z-STDLIB-RAW-MEMORY-BACKED-APIS-REQUIR-E503CD84` へ分ける。

## 2026-04-28 Stage 2 Resource IR skeleton 追記

`doc/neplg2/static_check_complexity_reduction_plan.md` の Stage 2 として、`nepl-core/src/resource/` に Resource IR の最小型、HIR lowering skeleton、deterministic dump を追加した。

今回の目的は enforcement ではなく可視化である。`ResourceModule`、`ResourceFunction`、`ResourceBlock`、`ResourceOp`、`Place`、`ResourceState` に加えて、今後の Stage 3-4 で必要になる `ResourceId`、`StorageId`、`CellState`、`OwnerState`、`BorrowState`、`PointerProvenance`、`EffectOp` を compiler-owned model として分けた。現行 `move_check` / `drop_insertion` にはまだ接続していないため、既存検査の意味論は変更していない。

HIR lowering skeleton は local read、let/set、borrow、drop、call effect、raw memory intrinsic を粗く Resource op として記録する。ただし Copy / move 判定、field offset、branch state merge、drop obligation の enforcement は Stage 3-4 へ残す。Stage 2 の dump snapshot test では、local declaration と read が安定した text dump に現れることを固定した。

次の作業は Stage 3 の local / aggregate / branch lowering である。ここでは HIR 直走査の raw alias summary を増やすのではなく、`Place` projection と `EffectOp` へ移す方向で進める。

## 2026-04-28 Stage 3 local / aggregate / branch lowering 追記

`doc/neplg2/static_check_complexity_reduction_plan.md` の Stage 3 commit 単位 1 として、Resource IR lowering が HIR の local / aggregate / branch 構造を失わないようにした。

今回の変更では、`ResourceOp::Expr` に出力 `Place` を持たせ、local read の `Read`、`DeclareLocal` の initializer、`Assign` の value、`Borrow` / `Move` の output を明示した。さらに tuple / struct / enum construction を `Construct`、`if` を nested `Branch`、`while` を `Loop`、`match` を `Match` として下げ、dump でも nested op を構造付きで確認できるようにした。

local lowering では HIR の `let` / `set` が式としては unit を返す仕様を守り、local place と式出力 temp を分離した。あわせて lowering context に local 型スコープを追加し、`drop x` の HIR 式型 unit を drop 対象型として誤用しないようにした。branch / loop / match arm の lowering では local scope を復元し、片側の branch や arm だけで宣言された local が外側の Resource IR lowering に漏れないようにしている。

この段階でも Resource IR はまだ enforcement へ接続していない。次の Stage 3 作業は raw memory operation lowering、function call / callback effect lowering、旧 checker との comparison diagnostics である。

## 2026-04-28 Stage 3 function call / callback effect lowering 追記

`doc/neplg2/static_check_complexity_reduction_plan.md` の Stage 3 commit 単位 3 として、function call と callback 境界を Resource IR で第一級に残すようにした。

今回の変更では `ResourceOp::Call`、`ResourceOp::IndirectCall`、`ResourceOp::FunctionValue`、`ResourceCallTarget` を追加した。direct call は target、argument places、output、effect を保持し、indirect call は callee place、parameter types、result type、argument places、output、unknown effect を保持する。`@fn` の function value も name と effect を持つ op として dump に出るため、Stage 4 で callback 候補と resource effect を dataflow で追える入力ができた。

あわせて Resource IR lowering に module-level effect map を追加し、`FuncRef::User` の effect を常に `Pure` として潰していた skeleton の問題を修正した。同名 overload / extern が混在する場合は安全側に `Impure` を優先する。これにより、direct call と function value の dump は現行 HIR 関数定義の surface effect を保持する。

この段階でも indirect call の concrete callee 解決や raw memory effect summary の適用はまだ旧 `move_check` 側に残っている。次の Stage 3 作業は old checker との comparison diagnostics であり、Resource IR lowering と既存 summary の差分を検出できるようにする。

## 2026-04-28 Stage 3 lowering coverage comparison 追記

`doc/neplg2/static_check_complexity_reduction_plan.md` の Stage 3 commit 単位 4 として、HIR と Resource IR lowering の coverage comparison diagnostic を追加した。

今回追加した `compare_hir_resource_lowering` は、HIR 側と Resource IR 側で direct call、indirect call、function value、raw memory operation の件数を関数単位で比較する。これは compiler 本体の診断挙動をまだ変えない debug 境界であり、Resource IR lowering が HIR の静的検査入力を落とした場合に test で検出できるようにする目的である。

既存 `move_check` の raw alias / function summary はまだ旧 HIR 走査側に残っているが、Stage 4 ではこの coverage 境界を足場として、`RawMemoryOp`、`Call`、`IndirectCall`、`FunctionValue` を `CellState` / `BorrowState` / `PointerProvenance` の検査へ接続する。coverage comparison は enforcement ではなく、移行中に lowering 欠落を隠さないための safety net として扱う。

## 2026-04-28 Stage 4 initialized / moved state 追記

`doc/neplg2/static_check_complexity_reduction_plan.md` の Stage 4 commit 単位 1 として、Resource IR 上で `CellState` による initialized / moved / dropped の検査を開始した。

今回追加した `check_resource_initialized_moves` は、関数 parameter を initialized cell として開始し、`DeclareLocal`、`Read`、`Assign`、`Move`、`Drop`、`Call`、`IndirectCall`、`RawMemory`、`Construct`、`Branch`、`Loop`、`Match` の Resource op を `CellState` の状態遷移として評価する。`TypeCtx::is_copy` を使い、Copy 値の read は元 place を維持し、non-Copy 値の by-value use は元 place を `Moved` にする。未初期化 cell、move 済み cell、drop 済み cell を使った場合は `ResourceCheckDiagnostic::CellUnavailable` として関数名、operation、place、state、span を保持する。

現時点では compiler pipeline の診断挙動をまだ切り替えていない。旧 `move_check` を弱めず、Resource IR 検査の結果を unit test で固定しながら移行するためである。また branch / loop / match の merge はまだ enforcement せず、`ResourceCheckDeferred` に deferred count として表面化した。これは Stage 4 commit 単位 4 の branch / loop merge で、現在の deferred 境界を実際の state merge に置き換える。

回帰テストでは、Copy 値の複数 read が通ること、non-Copy 値の二重 read が `Moved` として検出されること、drop 後 read が `Dropped` として検出されること、initializer なし local の read が `Uninit` として検出されることを `nepl-core/tests/resource_ir.rs` に固定した。

## 2026-04-28 Stage 4 borrow / lifetime 追記

`doc/neplg2/static_check_complexity_reduction_plan.md` の Stage 4 commit 単位 3 として、Resource IR 上で `BorrowState` による shared / unique borrow の競合検査を開始した。

今回追加した `check_resource_borrow_lifetimes` は、`ResourceOp::Borrow` の output を borrow token として source place に紐づける。shared borrow は shared count を増やし、unique borrow は active shared / unique borrow がない場合だけ許可する。active unique borrow 中の source read、active borrow 中の source assign / move / drop、shared borrow 中の unique borrow は `ResourceBorrowDiagnostic::BorrowConflict` として報告する。

borrow token の `Drop` は release として扱い、shared borrow count を減らす。`DeclareLocal` / `Read` / `Assign` / `Move` では borrow token の transfer を行う。ただし branch / loop / match の merge、関数境界での borrow summary、戻り値として escape する borrow の lifetime 検査はまだ後続 Stage に残す。現時点では compiler pipeline に接続せず、旧 `move_check` の防壁を維持しながら Resource IR 側の検査を regression で固定する。

回帰テストでは、shared borrow 中の read が通ること、unique borrow 中の source read が拒否されること、shared borrow 中の unique borrow が拒否されること、shared borrow release 後に unique borrow が通ることを `nepl-core/tests/resource_ir.rs` に固定した。

## 2026-04-28 Stage 4 branch / loop merge 追記

`doc/neplg2/static_check_complexity_reduction_plan.md` の Stage 4 commit 単位 4 として、Resource IR 上の `CellState` / `OwnerState` / `BorrowState` を branch / loop / match 後に合流するようにした。

`CellState` は片側だけ move / drop / uninit になる経路を `MaybeMoved` に合流し、後続 read / move / drop で `CellUnavailable` になる。`OwnerState` は片側で dealloc され、片側で live のまま残る経路を `MaybeFreed` に合流し、後続 dealloc や関数終了時の maybe leak を診断する。`BorrowState` は片側だけ active な shared / unique borrow も active として合流し、後続 mutation / move / drop を安全側に拒否する。

loop は「condition が少なくとも一度評価される」ことを反映し、condition 後 state と body 後 state を合流する。match は各 arm の state を合流する。これにより Stage 4 commit 単位 1-3 で `ResourceCheckDeferred` / `ResourceOwnerCheckDeferred` / `ResourceBorrowCheckDeferred` に残していた branch / loop / match の deferred count は、この範囲では 0 になる。

回帰テストでは、片 branch の non-Copy move 後 read、loop body の non-Copy move 後 read、条件付き dealloc 後の再 dealloc、片 branch の shared borrow 後 mutation を `nepl-core/tests/resource_ir.rs` に固定した。

## 2026-04-28 raw memory effect summary 追記

`move_check` の raw place state は direct call の検査を強化していたが、helper 関数内の raw memory operation を caller context へ伝播できず、関数境界で resource state が途切れる問題を `ISS-20260427T214055047Z-MOVE-CHECK-IGNORES-RAW-MEMORY-WRITES-417A7103` として修正した。

## 2026-04-28 indirect call effect summary 追記

関数境界の direct call summary に続き、function value / higher-order helper 経由で raw memory effect が落ちる問題を `ISS-20260427T215657067Z-MOVE-CHECK-LOSES-RAW-MEMORY-EFFECTS--BDFF8DD5` として修正した。

## 2026-04-28 enum payload function effect summary 追記

function value alias を通常の変数と parameter に保持するだけでは、`Option::Some @fn` などの enum payload を通過した時点で callback の resource effect が失われる問題を `ISS-20260427T221533970Z-MOVE-CHECK-LOSES-RAW-EFFECTS-THROUGH-308A8AC3` として修正した。

今回の補強では enum payload function alias を context stack と関数サマリへ追加し、`match` payload bind で function value alias を復元する。これにより現行 HIR 上の false negative は塞いだが、Resource IR では enum payload、function effect、raw initialized state を別々の補助 summary ではなく同じ resource state として表現する必要がある。

## 2026-04-28 memory model 方針レビュー追記

現在の raw memory 回帰修正は、既存 public API を壊さずに安全側へ寄せる移行措置としては意味がある。一方で、同じ方向を最終実装として継続するのは NEPLg2 の memory safety / effect 方針に対して適切ではない。

現状の複雑化は、`MemPtr` / raw `i32` / `RegionToken` / enum payload / callback / helper call / branch merge などを HIR 上の個別 summary で後追いしていることが原因である。この形では「何が owning resource で、何が non-owning pointer で、どの cell が initialized で、どこに drop obligation が残っているか」を compiler が単一の表現で保持できない。

したがって今後は個別 summary を積み増すのではなく、次の境界へ移す。

- safe surface から raw address escape を閉じ、raw operation は unsafe/internal boundary へ隔離する。
- `InternalAlloc` / `UnsafeMemory` 相当の internal effect を導入し、外へ raw identity が漏れない場合だけ surface `Pure` へ fold する。
- HIR 直走査ではなく Resource IR で owner token、borrow state、initialized state、drop obligation、pointer provenance を共有する。
- stdlib collection / string / selfhost buffer は `OwnedRegion` / `Storage` / builder token などの safe wrapper へ寄せ、`MemPtr<T>` を owner と pointer の兼用型として増やさない。

self-host は S1/S2 の lexer/parser/module loader など pure data model から開始できるが、S3 以降の move/resource/checker や raw memory backed buffer はこの設計移行を前提にする。
