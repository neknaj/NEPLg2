# ISS-20260426T010001Z-STDFS-WRITE-B7C4D923: std/fs lacks write and create interfaces required for self-host artifacts

## 概要

NEPLg2.0 self-host CLI は `.wasm`、LLVM IR、diagnostic JSON、dependency cache などをファイルへ出力する必要があるが、現行 `std/fs` は read 専用である。

## 対象

- `stdlib/std/fs.nepl`
- `stdlib/std/io.nepl`
- `stdlib/std/streamio.nepl`

## 根拠

- `fs_open_read`、`fs_read_fd_bytes`、`fs_read_to_bytes`、`fs_read_to_string` は存在する。
- `path_open` の write/create/truncate flags、`fd_write`、`fs_write_bytes`、`fs_write_string`、`FileWriter` に相当する public API がない。

## 問題

self-host compiler が artifact を外部へ保存できない。
stdout へ binary を流すだけでは、複数 artifact、cache、reproducible build 比較、CLI の `-o` 指定を実装できない。

## 影響

Stage 6 以降の Pass A / Pass B 比較が成立せず、セルフホスト完了条件を自動検証できない。
また、ユーザー向け CLI としてもコンパイル結果を明示的な output path へ書けない。

## 修正方針

`std/fs` に write 系を追加する。
最小 API は `fs_open_write`、`fs_write_fd_bytes`、`fs_write_to_bytes`、`fs_write_to_string`、`fs_close` とする。
WASI は preopen root 内の relative path を前提にし、create/truncate/write rights を明示する。
LLVM は Linux syscall 互換実装を既存 `__fs_syscall` 経路に追加する。

## 検証

- 存在しない一時ファイルへ `fs_write_to_string` し、`fs_read_to_string` で一致を確認する doctest。
- binary NUL を含む `ByteBuf` を書き戻して長さと内容を確認する doctest。
- preopen 外 path の拒否を CLI / WASI 側で確認する integration test。
