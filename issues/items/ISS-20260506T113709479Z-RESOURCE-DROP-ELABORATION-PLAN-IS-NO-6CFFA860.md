# ISS-20260506T113709479Z-RESOURCE-DROP-ELABORATION-PLAN-IS-NO-6CFFA860: Resource drop elaboration plan is not consumed by HIR drop call generation

## 概要

Stage 4 now computes checked ScopeLocal and AssignmentOverwrite drop facts in ResourceDropElaborationPlan, but compiler.rs still calls legacy HIR passes::insert_drops. That pass walks HIR with its own VarState/scope state and remains a second drop authority.

## 対象

- `nepl-core/src/passes/drop_insertion.rs, nepl-core/src/compiler.rs, nepl-core/tests/resource_ir.rs, nepl-core/tests/check_pipeline.rs, nodesrc/test_resource_gate_order.js`

## 根拠

`doc/neplg2/static_check_complexity_reduction_plan.md` Stage 4 は、move / borrow / lifetime / drop obligation を Resource IR 上の checked state へ移すことを完了条件にしている。直前まで `ResourceDropElaborationPlan` は checked live drop fact として構築・検証されていたが、実際の HIR drop call 生成は `passes::insert_drops` の HIR scope walker が担当していた。

この状態では Resource IR が static-check authority になっても、codegen の drop 対象だけは HIR 側の `VarState` / scope stack 推定で決まる。Stage 4 の設計上、これは別 authority であり、残すべきではない。

## 問題

Stage 4 now computes checked ScopeLocal and AssignmentOverwrite drop facts in ResourceDropElaborationPlan, but compiler.rs still calls legacy HIR passes::insert_drops. That pass walks HIR with its own VarState/scope state and remains a second drop authority.

## 影響

Static check cannot be considered authoritative while actual drop calls are generated by a separate HIR state walker. Removing the walker without a plan consumer would miss scope or assignment overwrite drops, while keeping it leaves technical debt and can diverge from Resource IR checked facts.

## 修正方針

Replace the compiler drop elaboration step with a ResourceDropElaborationPlan consumer that inserts drop calls from checked plan points. The implementation must distinguish ScopeLocal and AssignmentOverwrite by enum, generate calls from ResourceDropRequirement, and avoid HIR VarState inference.

## 対応結果

`nepl-core/src/passes/drop_insertion.rs` を `ResourceDropElaborationPlan` consumer として作り替えた。public API は `insert_resource_drops` になり、`ResourceAutoDropKind::ScopeLocal` と `ResourceAutoDropKind::AssignmentOverwrite` を enum match で分けて処理する。drop call の分類は `ResourceDropRequirement` を消費し、旧 `VarState`、`var_stacks`、HIR scope-local state inference は削除した。

`prepare_module_for_codegen_with_source_map` は 1 回の typecheck から drop 未挿入の reachable monomorphized HIR を作り、Resource IR static check と bridge gate を通過した後、同じ HIR に checked plan から drop call を挿入する。挿入後は final monomorphize を再実行し、生成された Drop trait call を concrete user call へ解決する。これにより、従来の「Resource IR 用 HIR」と「legacy HIR drop insertion 用 HIR」を二重 typecheck で分ける暫定経路を削除した。

plan-based drop insertion は最初の monomorphize 後に Drop call を追加するため、その時点で未到達だった Drop impl method body が final monomorphize の入力から落ちる問題も合わせて修正した。`monomorphize_internal` は `HirModule.impls[*].methods[*].func` を function table に再登録し、生成 Drop trait call が concrete impl method へ解決された後、その call target body も final HIR に残るようにした。

未消費の codegen-needed drop point は `ResourceDropInsertionError` として返すため、checked plan と HIR anchor がずれた場合に黙って drop を欠落させない。source policy も `passes::insert_drops` と `VarState` walker の再導入を拒否するように更新した。

関連 stage: [静的検査の複雑化解消計画 Stage 4](../../doc/neplg2/static_check_complexity_reduction_plan.md#stage-4-resource-check-への移行)
