# RV-CORE-010: name resolution が二重化し本パイプラインに統合されていない

旧 `doc/review20260425` から移行した Issue。新しい正の ID は `ISS-20260425T000000Z-RV-CORE-010-05C6281D`。

## 要約

名前解決の意図は `resolve.rs` と `name_resolve.rs` にありますが、本 pipeline は `typecheck.rs` 内 Env に依存しています。DefId を持つ canonical resolution になっていません。

## 影響

import alias、overload、shadowing、qualified path の責務が分散し、同名関数や module boundary のバグが出やすくなります。

## 修正方針

`name_resolve.rs` は削除または `resolve/` へ統合し、DefId を AST/HIR lowering の入力にします。`typecheck.rs` の Env は型検査用 local binding に限定します。

## 検証

cross-file import、qualified alias、shadowing、ambiguous open import の tree test を DefId snapshot として追加します。

## 解決

2026-04-27 に main pipeline の import 名前解決を `resolve.rs` の `ImportResolution` に統合した。

- `nepl-core/src/name_resolve.rs` の未使用 skeleton を削除し、名前解決の入口を `resolve.rs` に一本化した。
- `typecheck.rs` 内にあった SourceMap ベースの qualified / unqualified import visibility helper を `resolve.rs` の public API へ移した。
- `typecheck.rs` は `ImportResolution` から候補 file set と未修飾可視性を問い合わせるだけになり、`Env` は local binding / overload / 型検査候補の管理に限定した。
- `resolve.rs` は no_std core からも参照できるよう常時公開し、ModuleGraph / DefId / ExportTable 系 API は host-only cfg に分離した。
- alias、selective alias、merge facade の SourceMap resolver snapshot を `nepl-core/tests/resolve.rs` に追加した。

- `node nodesrc/tests.js -i tests/compiler/resolve.n.md -i tests/compiler/shadowing.n.md --no-tree -o tmp/core-resolve-integration.json -j 1`: total 39, passed 39
- `node nodesrc/issues.js check`: pass

残課題:

- HIR の `FuncRef::User` は引き続き backend symbol 文字列を保持しており、stable DefId snapshot そのものはまだ HIR に埋め込まれていない。これは今回の import resolution 統合と独立した後続設計 issue `ISS-20260427T011048496Z-HIR-FUNCTION-REFERENCES-STILL-LACK-S-5EF51F12` として分離した。
