# RV-STDLIB-007: str の UTF-8 保証が実装で守られていない

旧 `doc/review20260425` から移行した Issue。新しい正の ID は `ISS-20260425T000000Z-RV-STDLIB-007-9CDFD520`。

## 要約

`str` 型が UTF-8 保証を持つ仕様なのに、filesystem / byte buffer から検証なしで `str` を作る経路があります。これにより `str` として不正な byte列が入り得ます。

## 影響

文字列 API、HTML/NM generator、debug/serialize が UTF-8 前提で動く場合に壊れます。将来 `char` / Unicode 処理を追加するとさらに深刻になります。

## 修正方針

`ByteBuf -> str` は UTF-8 validate を必須にし、失敗時は `Result::Err` を返します。raw bytes が必要な API は `ByteBuf` のまま扱います。

## 解決内容

- `alloc/io` の `io_bytebuf_to_str_result` を unchecked copy から UTF-8 検証付きの境界に変更し、invalid UTF-8 を `StdErrorKind::InvalidUtf8` として返すようにした。
- `std/fs` の `fs_bytes_to_string_result` / `fs_read_to_string` は、この checked 境界に委譲することを仕様コメントとして明確化した。
- `std/fs` の `fs_string_from_bytes` も directory entry name byte range を `str` にする前に UTF-8 検証し、invalid entry は errno 84 (ILSEQ 相当) として返すようにした。
- `std/text` の説明を更新し、source text 向け API と全体の `ByteBuf -> str` 境界がどちらも checked であることを整理した。
- `tests/stdlib/text_utf8.n.md` と `nodesrc/test_stdlib_bytebuf_utf8_boundary.js` に、invalid UTF-8 が `str` 化されないことを監視する回帰テストを追加した。
