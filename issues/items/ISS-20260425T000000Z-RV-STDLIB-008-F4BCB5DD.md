# RV-STDLIB-008: self-host compiler がプレースホルダのまま

旧 `doc/review20260425` から移行した Issue。新しい正の ID は `ISS-20260425T000000Z-RV-STDLIB-008-F4BCB5DD`。

## 要約

self-host compiler のディレクトリは存在しますが、実装はありません。`core/ast`, `parser`, `typecheck`, `diagnostic`, `span`, `cli/main` が同じ placeholder 形式です。

## 影響

セルフホスト計画の進捗が実装から判別できません。Rust compiler の分割計画と NEPL 側 module の対応表も未確立です。

## 修正方針

まず `span`, `diagnostic`, `ast token subset`, `lexer` の最小実装から milestone を切ります。placeholder file には TODO ではなく、実装段階と依存関係を明記します。

## 2026-04-28 再レビュー

この issue の元の対象は `stdlib/neplg3/**` だったが、現在の正規 self-host tree は `doc/neplg2/self_host_plan.md` に従い `stdlib/neplg2/**` である。

現在は Stage 0 skeleton から進み、`core/infra/span.nepl`, `core/infra/text.nepl`, `core/infra/diag.nepl`, `core/infra/outcome.nepl`, `core/syntax/token.nepl`, `core/syntax/lexer.nepl`, `cli/args.nepl` は実行可能な実装を持つ。一方で `core/syntax/parser/module_parser.nepl`, `core/module/loader.nepl`, `core/ty/ty.nepl`, `core/check/checker.nepl`, `core/hir/hir.nepl`, `core/resource/move_state.nepl`, `core/mono/mono.nepl`, `core/codegen/wasm/binary.nepl`, `core/codegen/llvm/text.nepl`, `core/pipeline.nepl`, `cli/main.nepl` はまだ Stage 0 smoke API であり、現行 compiler の pipeline へ接続していない。

self-host 実装を今始められるかという観点では、S1 の lexer/parser と S2 の in-memory module loader は開始可能。ただし full self-host compiler としては未開始相当で、以下を先に具体 issue として追跡する。

- `ISS-20260428T000125736Z-SELF-HOST-LEXER-LACKS-OFFSIDE-TOKENS-3BD65FA4`: lexer が offside token と Rust lexer parity fixture を欠く。
- `ISS-20260428T000139506Z-SELF-HOST-SOURCETEXT-BUILDS-LINE-MAP-A6115235`: SourceText line map 構築が byte ごとの再帰で、大入力に弱い。
- `ISS-20260428T000149871Z-SELF-HOST-CLI-ARG-CLASSIFIERS-USE-NE-25938DB7`: CLI arg classifier に match 化すべき有限分岐の nested if が残る。
- `ISS-20260428T000208719Z-SELF-HOST-CLI-EMIT-OPTION-CANNOT-REP-FC7EB52D`: `--emit` が複数 artifact を表せない。

core 側では `ISS-20260425T000000Z-RV-CORE-009-58589A3F` と raw memory/provenance 系 open issue が S4 以降の blocker である。borrow checker 周辺は別 agent が進めているため、この issue では S1-S3 の stdlib/neplg2 側実装単位へ分割して進める。

## 2026-04-28 S2 進捗

- `ISS-20260428T123612100Z-SELF-HOST-MODULE-LOADER-LACKS-IN-MEM-7C7A197A` で `core/module/loader.nepl` に in-memory VFS と `path -> source -> SelfhostModuleAst` の入口を追加した。
- VFS loader は filesystem に依存せず、missing file を `SelfhostDiagnostic` として返す。これにより S2 の import graph / stdlib map を parser へ接続する最低限の境界ができた。
- `ISS-20260428T123810929Z-SELF-HOST-LEXER-HARDCODES-SOURCE-FIL-B72A7A74` で lexer/parser に file_id aware entry point を追加し、VFS loader が追加順 file_id を AST item span へ渡せるようにした。
- `ISS-20260428T141156276Z-SELF-HOST-MODULE-LOADER-LACKS-TYPED--7277C7AB` で import directive を `SelfhostImportSpec` として構造化し、path / alias / wildcard を module 層の typed boundary にした。
- `ISS-20260428T145201247Z-SELF-HOST-MODULE-LOADER-LACKS-IMPORT-F2C1CBCA` で root module から VFS logical path 上の import graph を構築し、missing module と cycle を diagnostic として返す S2 graph 境界を追加した。
- `ISS-20260428T155038303Z-SELF-HOST-MODULE-LOADER-LACKS-STDLIB-B3D12B30` で stdlib root / user root の logical path mapping を追加し、mapped import graph が `core/result` と `./util` を同じ VFS graph に載せられるようにした。

- 同 issue で `cli/reporter.nepl` を追加し、単一 diagnostic と collection の human / JSON rendering API、Result 付き stdout/stderr write helper、source policy regression を整備した。remote main の Vec provenance 修正を取り込んだ後、collection fixture も green にした。

- 同 issue で `cli/driver.nepl` を追加し、VFS と parsed options から root module load を行う driver result 境界を実装した。missing input / missing file / success の exit code と diagnostics を固定し、reporter への委譲と stdio/fs 非依存を source policy で検査している。

## 2026-04-29 S6 CLI file_io 追跡

- 同 issue で `cli/file_io.nepl` を追加し、root source の checked read -> VFS 登録、text/binary artifact write、filesystem error の diagnostic 化を実装した。source policy で `std/fs` import を file_io に閉じ込め、driver / core pipeline の filesystem 非依存境界を維持した。

## 2026-05-18 pre-implementation source tree review

- `ISS-20260518T140937691Z-SELF-HOST-SOURCE-TREE-PLAN-MUST-BE-R-5C746649` で、self-host 実装をさらに進める前のディレクトリ構造とファイル分割方針を再検討した。
- 現行 Rust 実装は `nepl-core/src` が 382 files / 約 79,607 行、root 直下だけで 36 files / 約 27,732 行あり、`parser.rs` / `codegen_llvm.rs` / `codegen_wasm.rs` / `compiler.rs` / `types.rs` / `loader.rs` が flat な巨大 file として残っている。
- self-host 側も部分実装段階で `core/syntax/lexer.nepl` 1,329 行、`core/hir/hir.nepl` 1,036 行、`core/syntax/token.nepl` 864 行、`core/ty/ty.nepl` 769 行まで肥大化しているため、今後の実装は [doc/neplg2/self_host_source_tree_layout_review_20260518.md](../../doc/neplg2/self_host_source_tree_layout_review_20260518.md) の階層化方針に従う。
- 特に、`checker.nepl`、`pipeline.nepl`、parser、typecheck、Resource IR、codegen に Rust 側の flat 構造を移植しない。静的検査は `core/proof/` の汎用 fact / obligation / solver に接続し、owner / initialized / borrow / effect / abstraction check が個別 ad hoc 証明器を持たないようにする。

## 2026-05-18 S3 checker boundary 進捗

- `ISS-20260518T141535025Z-SELF-HOST-CHECKER-REMAINS-A-STAGE0-M-40624575` を fixed にした。
- `doc/neplg2/self_host_source_tree_layout_review_20260518.md` の P1 方針に従い、checker 実装本体は root の `checker.nepl` へ置かず、`stdlib/neplg2/core/check/module.nepl` に module item stream validation と summary を分離した。
- `SelfhostModuleItemKind` の exhaustive match で doc comment / directive / declaration / raw backend block を分類し、文字列 kind や stdlib/module allowlist を証明として扱わない形にした。
- `selfhost_pipeline_check_loaded_root` を追加し、load 済み root AST を checker boundary へ接続した。これにより S2 loader から S3 checker へ進む最小の typed pipeline ができた。
- checker diagnostic は `SelfhostDiagnosticCode::Checker(SelfhostCheckerDiagnosticCode)` で階層化した。primary label 付き diagnostic は Resource IR owner check が span metadata を owner payload と誤分類するため、`ISS-20260518T142248720Z-RESOURCE-IR-OWNER-CHECK-MISCLASSIFIE-8A3C73E5` に分離している。

## 2026-05-20 S3/P1 proof entry 進捗

- `ISS-20260519T204942256Z-SELF-HOST-CHECKER-LACKS-A-GENERIC-PR-35D60062` を fixed にした。
- `stdlib/neplg2/core/proof.nepl` と `core/proof/{fact,obligation,query,solver}.nepl` を追加し、self-host static checker が使う汎用 proof entry point を final hierarchy に置いた。
- 初期 solver は source span validity だけを扱うが、fact / obligation / result kind は enum payload で定義し、`match` による網羅分岐で照合する。これにより、新しい静的検査が module checker-local proof として増える入口を塞ぐ。
- `check/module.nepl` は `source_span_is_valid item.span` を直接呼ばず、`selfhost_proof_source_span_valid item.span` を通す。`checker.nepl` は orchestration-only のままとし、proof 実装を抱え込まない。
- 残る self-host checker 作業では、raw backend block 状態、declaration well-formedness、trait coherence、effect boundary、Resource IR owner/initialized/borrow obligation を同じ `core/proof/` の fact / obligation domain へ順に追加する。

## 2026-05-20 S3/P1 source span proof result 進捗

- `ISS-20260519T213705215Z-SELF-HOST-SOURCE-SPAN-PROOF-COLLAPSE-EB18F406` を fixed にした。
- source span validity は `bool` ではなく `Result<(), SelfhostProofRefutation>` を返す API に変更し、`SelfhostProofRefutation::SourceSpanInvalid` を checker diagnostic へ渡す形にした。
- `selfhost_proof_result_is_proven` は削除し、proof layer の public boundary が typed evidence/refutation を boolean predicate へ潰さないようにした。

## 2026-05-20 S3/P1 raw backend proof 進捗

- `ISS-20260519T210448628Z-SELF-HOST-RAW-BACKEND-BLOCK-VALIDATI-FA9ABCD2` を fixed にした。
- `check/module.nepl` に残っていた raw backend block state machine を `core/proof` の typed fact / obligation / evidence / refutation へ移した。
- module checker は `SelfhostModuleItemKind` を `SelfhostRawBackendItemKind` へ写し、`selfhost_proof_raw_backend_transition` の typed refutation を checker diagnostic に変換するだけになった。`SelfhostModuleRawState` は削除済み。
- 残る P1 は declaration well-formedness、trait coherence、effect boundary、Resource IR owner/initialized/borrow obligation の proof domain 追加である。

## 2026-05-20 S3/P1 module directive proof 進捗

- `ISS-20260519T212225940Z-SELF-HOST-MODULE-DIRECTIVE-MULTIPLIC-33C1FBE9` を fixed にした。
- `#entry` / `#target` の重複検査は summary count の後処理ではなく、`SelfhostModuleDirectiveFact` と `SelfhostModuleDirectiveState` の typed transition proof として `core/proof` に置く。
- module checker は `SelfhostModuleItemKind` を singleton directive kind に写し、proof refutation を checker diagnostic へ変換するだけにする。これにより S3 module well-formedness も checker-local ad hoc proof へ増えない。

## 検証

`stdlib/neplg3/core/span.nepl` など最小 module ごとに doctest を実行可能にし、skip を外します。
