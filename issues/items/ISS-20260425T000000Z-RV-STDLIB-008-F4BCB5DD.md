# RV-STDLIB-008: self-host compiler がプレースホルダのまま

旧 `doc/review20260425` から移行した Issue。新しい正の ID は `ISS-20260425T000000Z-RV-STDLIB-008-F4BCB5DD`。

## 要約

self-host compiler のディレクトリは存在しますが、実装はありません。`core/ast`, `parser`, `typecheck`, `diagnostic`, `span`, `cli/main` が同じ placeholder 形式です。

## 影響

セルフホスト計画の進捗が実装から判別できません。Rust compiler の分割計画と NEPL 側 module の対応表も未確立です。

## 修正方針

まず `span`, `diagnostic`, `ast token subset`, `lexer` の最小実装から milestone を切ります。placeholder file には TODO ではなく、実装段階と依存関係を明記します。

## 2026-04-28 再レビュー

この issue の元の対象は `stdlib/neplg3/**` だったが、現在の正規 self-host tree は `doc/neplg2/self_host_plan.md` に従い `stdlib/neplg2/**` である。

現在は Stage 0 skeleton から進み、`core/infra/span.nepl`, `core/infra/text.nepl`, `core/infra/diag.nepl`, `core/infra/outcome.nepl`, `core/syntax/token.nepl`, `core/syntax/lexer.nepl`, `cli/args.nepl` は実行可能な実装を持つ。一方で `core/syntax/parser/module_parser.nepl`, `core/module/loader.nepl`, `core/ty/ty.nepl`, `core/check/checker.nepl`, `core/hir/hir.nepl`, `core/resource/move_state.nepl`, `core/mono/mono.nepl`, `core/codegen/wasm/binary.nepl`, `core/codegen/llvm/text.nepl`, `core/pipeline.nepl`, `cli/main.nepl` はまだ Stage 0 smoke API であり、現行 compiler の pipeline へ接続していない。

self-host 実装を今始められるかという観点では、S1 の lexer/parser と S2 の in-memory module loader は開始可能。ただし full self-host compiler としては未開始相当で、以下を先に具体 issue として追跡する。

- `ISS-20260428T000125736Z-SELF-HOST-LEXER-LACKS-OFFSIDE-TOKENS-3BD65FA4`: lexer が offside token と Rust lexer parity fixture を欠く。
- `ISS-20260428T000139506Z-SELF-HOST-SOURCETEXT-BUILDS-LINE-MAP-A6115235`: SourceText line map 構築が byte ごとの再帰で、大入力に弱い。
- `ISS-20260428T000149871Z-SELF-HOST-CLI-ARG-CLASSIFIERS-USE-NE-25938DB7`: CLI arg classifier に match 化すべき有限分岐の nested if が残る。
- `ISS-20260428T000208719Z-SELF-HOST-CLI-EMIT-OPTION-CANNOT-REP-FC7EB52D`: `--emit` が複数 artifact を表せない。

core 側では `ISS-20260425T000000Z-RV-CORE-009-58589A3F` と raw memory/provenance 系 open issue が S4 以降の blocker である。borrow checker 周辺は別 agent が進めているため、この issue では S1-S3 の stdlib/neplg2 側実装単位へ分割して進める。
