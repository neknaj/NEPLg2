# 進捗レポートの書き方

## 形式

タイトルを1行で要約し、`#` 見出し1行目に入れる。  
例: `# 進捗報告: 2026-04-25 — Discord Webhook の投稿名を固定`

本文は `##` で固定。最低3セクションを入れる。

- `## 直近の改良`
- `## これからする内容`
- `## 検証`

`直近の改良` の中に、通常作業とIssue対応を分けて整理し、Issueがある場合は `Issue対応` として丁寧に解説する。  
`Issue対応` は別セクションにせず、`## 直近の改良` 内に含める。

## テンプレート

```text
# 進捗報告: 2026-04-25 — Discord投稿レポートの仕様を更新

## 直近の改良
- 通常改良: Discord投稿時の表示名を `NEPLg2 dev report` に固定
- Issue対応:
  - Issue: #123
  - 問題: メッセージ長分割時にタイトルが分かりづらかった
  - 調査: 既存仕様ではタイトルと本文の分離が不十分だった
  - 対応: 見出しルールを 1行サマリーに変更し、Issue背景を追記
  - 影響: 事後報告の再現性と追跡性が向上

## これからする内容
- 再試行失敗時の挙動を1件ずつ1行化
- 追加Issueの再現手順を `Issue対応` に追記する

## 検証
- `node nodesrc/cli.js --discord "check"` 成功（discord sent）
- `node nodesrc/cli.js -i tests/playground_editor --playground-editor-tests -o json=...` 成功
```

## ルール

- 1行で要約可能な項目は1行で書く
- Issue対応は `直近の改良` 内で `Issue対応` として記載
- `## 検証` は成功/失敗を明示
- 未完了は `未対応` または `未確定` を明記
- `#` / `##` を必ず使う
- Discord にはこの Markdown 本文を直接送信し、ファイルパス参照だけの報告にしない
